# 周期费用与下次扣费

2026-11-14，SCAU Link 0.8.1。真实环境只查询用户已保存的首个自有账号；没有停止或重启联网进程，没有执行 EAP 登录、退出、暂停、恢复或支付。

## 数据来源

固定学校主机 `https://mavis.scau.edu.cn:8443`。沿用已验证的原客户端账号信息查询及独立业务详情会话；不读取浏览器 Cookie，不执行网页脚本，不跟随重定向。

此前只请求 `GET /selfservice/module/userself/web/portal_packagemoney.jsf`，该页提供余额、套餐名称和周期范围，没有明确的月费和下次扣费字段。

学校自己的 `index_self.js` 将“我的套餐”指向 `GET /selfservice/module/userself/web/consume.jsf`。该页面实际提供 `totalTable` 表格：

| 标签 | 处理 |
| --- | --- |
| 余额、当前套餐 | 与账号摘要及旧详情页交叉核对；冲突时不合并新的费用信息 |
| 计费策略 | 接受观察到的严格格式 `周期<天数>天<金额>元`，例如合成夹具 `周期31天24.50元` |
| 周期时间范围 | 完整起止日期，按含首尾的天数与计费策略再次核对 |
| 用户状态 | 只有明确“正常”才允许展示续期估算 |
| 消费、待扣款 | 不当作周期定价或月费，不据此推算下一次实际扣费 |

原生正式查询增加一个按需 GET，共用该账号本次建立的临时业务会话；遵循已有 5 分钟缓存、账号及凭据版本隔离、隐藏／小窗／静默不主动查询规则。新页面失败、跳转、字段缺失、余额／套餐／周期冲突时，保留已经取得的余额与本期范围，新字段保持未知。

研究探针先调用官方只读首页刷新并核对 `userId` 确属自身，再读取上述页面。`needFee` 在真实响应中不是单期费用，`feeExpirationTime` 也不能证明是下次扣费日期；没有将它们猜测映射到月费、下次扣费或完整账户失效日期。业务明细页面没有提供本账号的财务明细入口，本次没有调用受限的账务页面。

## 展示与日期边界

按固定天数计费的套餐显示“每 N 天扣费”，不将 31 天等同于自然月。明确的月费字段仍单独保留。

学校没有直接返回确定的下一次扣费时间。只在余额足以支付单期费用、服务正常、当天处于已核对的有效周期、固定天数与周期范围一致时，将周期末日的下一天显示为 **预计下次扣费**。它是下个周期的续期估算，独立于服务器明确返回的 `next_charge`；不会虚构时分，不保证实际扣款发生，暂停、欠费、套餐变化等可能改变实际结果。过期周期、未来周期和非正常状态不生成估算。

优先显示服务器明确的下次扣费日期与时间。自然月费用与固定天数策略不混合用于估算；完整账号失效日期也不由余额除以单期费用计算。

## 验证

- 新增离线请求流程测试：固定 GET 路径、业务会话隔离及 Cookie 更新、取消、跳转／网络失败、余额／套餐／周期不一致时的回退。
- 费用与日期测试：零费用、异常金额、重复策略、周期长度矛盾、暂停、余额不足、当前周期有效性、闰年及跨年；明确区分实际日期与估算日期。
- 真实账号原生只读探针确认新页面 HTTP 200、余额／套餐／周期一致、周期费用可用、续期估算可用；服务器明确的下次扣费字段仍不可用。探针不输出凭据、账户身份、金额或原始响应。
- 原生界面仅使用演示数据检查普通与周期费用并列、预计标签、选中横条及窄窗口；截图不含真实账户资料。
