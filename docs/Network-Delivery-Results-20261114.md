## 修复与对照

1. **WLAN 网络配置存储。** 同一接口、账号和 PEAP 参数下，当前用户网络配置没有完成认证；直接 C++ 探针也复现。改用所有用户网络配置约一秒完成 EAP，真实桌面应用得到相同结果。0.11.1 默认采用此存储；随机配置名、manual 与归属校验仍保留。`WlanSetProfileEapXmlUserData` 的 flags 仍为 0，没有向所有 Windows 用户提供凭据。该结果证明本机的兼容差异，不推断其他主机一律存在同样问题。
2. **主机地址配置。** WLAN 原先关闭 IPv4 DHCP，且没有有效静态 IPv4/DNS。此前已成功的 EAP 没有产生可用的 IP 地址。用户确认 UAC 后，实验看门狗临时开启该 WLAN 的 DHCP 与自动 DNS；客户端和恢复后的原客户端始终通过 Explorer 以普通权限启动。最终恢复了原配置，应用本身没有自动改动 IP 设置。
3. **实验脚本。** 核心重登后也需要等待 DHCP，原本立即探测会产生假失败；现在与首次连接一样最多等待 45 秒。原 disabled/empty IPv4 状态在 Windows 常规接口下无法可靠还原，恢复逻辑增加了仅针对原物理接口的精确回退，最终已真实核验。
4. **状态日志竞争。** 第 10 轮被实验自身异常中止，原客户端自动恢复；旧日志仅保留 `local_preflight_error`，不足以追溯具体系统错误。随后加入 Windows 短暂文件共享锁的有限重试和安全的异常类型/数值记录，新增两项真实 Windows 文件锁检查。最终第 11 轮完整通过。旧失败记录仍保留，没有改写为成功。

本轮前序实验的原始日志位于 `captures/delivery-lab-20261114-01` 至 `-10`。第 09 轮已完成无线认证、上网与核心重登，但在重登后立即进行的上网探测处失败；其历史 `result.json` 保留失败，后续手动恢复与最终完整重测分别记录。旧 WinPcap 在 WLAN 媒体切换时丢失句柄，未取得有效无线抓包；本报告使用 WLAN ACM/ONEX 通知和实际接口绑定访问证明结果。
