# 0.14.4 登录自启与有线驱动诊断

开启“开机自启”后，使用当前用户的 Windows 登录任务代替普通 Run 启动项。任务没有额外延迟，使用正常调度优先级，不等待空闲、外接电源或已有网络，不保存 Windows 密码、不提权；运行不设时长上限，重复触发忽略新实例。它在用户登录后启动，不提供登录前的系统服务认证，也不保证抢在所有 Windows 服务之前运行。

启用状态从旧版迁移：新版首次正常运行、或安装程序更新路径时，先注册任务，成功后清除旧 Run 项。注册失败保留旧方式并记录错误。关闭自启移除任务；卸载只移除指向当前安装路径的任务，保留其他便携副本的任务。安装辅助命令只维护自启，不读取校园凭据或启动认证。

连接线程通过 Windows 网卡变化通知唤醒，同时最多每 100 毫秒复查驱动及取消状态。有线链路就绪即可开始二层认证，不以取得 DHCP 地址或访问互联网为前提。驱动处于启动中时等待最多 30 秒；已经配置的备用连接方式仍遵循原有超时和切换规则。

检测对应 Npcap/WinPcap 驱动服务；服务停止时尝试使用当前权限启动，不修改服务启动类型。缺失、启动中、权限不足或启动失败分别提示。抓包库存在不再等同于驱动可用。网卡打开失败在认证进程进入 ready 之前也能通过私有通道传递固定中文说明，不泄露原始驱动输出、不作为密码错误轮换账号。

本机故障证据：旧 WinPcap 4.1 的 NPF 服务处于停止、手动启动状态；普通权限尝试启动返回错误 5（拒绝访问）。对应有线日志在网卡打开阶段失败，不能归因于校园密码错误。较早记录另有发送 Start 后未获服务器回应的情况，仍需驱动恢复后重新观察。

本版不会安装驱动、请求自动提权、调整其他启动项或断开现有连接。该电脑仍需由管理员启动/修复抓包驱动；仅升级客户端不能绕过 Windows 服务权限。若使用 Npcap，需确保安装及网卡绑定完整，并配置允许客户端访问的权限。
