# 套餐摘要失败诊断与详情查询恢复

0.14.2，2026-11-15。发布状态以 [GitHub Release](https://github.com/Hubujiu/SCAU-Link/releases/tag/v0.14.2-preview) 为准。

## 本次日志能证明什么

测试人员提供的日志包含两次完整的诊断事件组：阶段为 Summary（2），HTTP 状态为 200，socket/TLS 错误为 0，最终状态为 Unsupported（7）；详情和计费页的 HTTP 状态均为 0。说明请求已进入账号摘要阶段，尚未进入详情页，不能解释为没有启动查询或没有保存凭据。

旧日志未记录传输结果枚举、HTTP 正文完整性和摘要解析结果。因此不能仅凭 HTTP 200 断言自助服务登录成功、正文完整、密码错误，或学校没有提供余额。浏览器被安全策略拦截也不能验证同一账号的自助服务登录结果。原始日志及响应不进入仓库或安装包。

## 确认并修复的代码缺陷

原查询在摘要中没有识别出余额、费用、名称等可显示字段时直接返回，详情入口未被检查。现在独立验证响应中的已知详情入口：即使摘要的显示字段缺失，只要存在合法入口，仍建立该次查询的隔离会话，读取套餐和计费详情。

不猜测登录路径，不执行返回脚本，不跟随外部链接；只允许原有固定学校路径、参数和只读页面。没有有效入口时仍保留失败状态，缺失数据不显示为零。详情页数据仍遵守已有的金额、套餐名及账期一致性检查。此缺陷已用合成响应复现并加入回归，但旧日志不足以证明它就是报告电脑的唯一根因。

摘要与详情入口复用同一个有界信封解析器，兼容已知 JSON、`ballInfo(...)` 包装及 BOM；不接受任意 JavaScript、网页或猜测字段。

## 新增诊断

`%LOCALAPPDATA%\ScauLink\logs\desktop.jsonl` 新增以下数字/布尔信息，保留原有阶段及状态事件：

| 事件 | 含义 |
| --- | --- |
| `package_query_transport_state` | 0 完成，1 网络错误，2 TLS 错误，3 HTTP 协议错误 |
| `package_query_http_complete` | 是否取得完整 HTTP 响应 |
| `package_query_response_bytes` | 已解析响应体的字节数 |
| `package_query_summary` | 下表中的解析结果 |
| `package_query_summary_items` | 摘要信息项数量 |
| `package_query_detail_route` | 是否识别到合法详情入口 |
| `package_query_detail_login_http` | 详情登录请求的 HTTP 状态 |
| `package_query_detail_session` | 是否获得合法临时会话 |
| `package_query_balance_available` / `package_query_fee_available` | 最终余额/费用是否可用，不记录具体金额 |

| 摘要结果 | 含义 |
| --- | --- |
| 0 | 尚未检查正文 |
| 1 | 空内容 |
| 2 | 字符编码无法解码 |
| 3 | 返回网页/标记内容，未取得账号摘要 |
| 4 | JSON 或已知包装无法解析 |
| 5 / 6 | 缺少账号摘要 / 摘要类型不兼容 |
| 7 / 8 | 缺少信息列表 / 列表类型不兼容 |
| 9 / 10 | 空列表 / 超出信息项限制 |
| 11 | 列表可解析，但未识别到余额等字段 |
| 12 | 已识别到至少一个已知字段 |
| 13 | 响应超出大小限制 |
| 14 | HTTP 响应不完整或协议格式异常，未解析摘要 |

“记录”页现在显示套餐完成、部分信息、失败及摘要解析说明，支持状态筛选与搜索“套餐”；旧日志中的 `package_query_state` 同样可以显示。原始字段、服务器文本、Cookie、账号和密码不进入页面。底层逐项诊断保留在文件中，不让每次查询产生十多行界面记录。

## 复测

确认实际运行 0.14.2，在普通窗口的已连接主页等待约两分钟。若仍失败，发送 `desktop.jsonl`、出错时间、连接方式和版本即可，无需账号密码或学校原始响应。正常查询完成后五分钟刷新；错误及缺失信息的重试规则与 [0.14.1](Package-Query-0.14.1.md) 相同。

本轮验证范围及限制见 [验证报告](Network-Delivery-Results-0.14.2.md)。
