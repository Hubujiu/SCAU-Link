## 已修复的具体问题

1. 现网 Web 使用 `InterFace.do` 和浏览器兼容 User-Agent。旧 authAPI 的登录响应不代表其状态查询也可用；现网空服务对象 `{}` 也不能按数组处理。已适配同源表单编码、服务数据、保活和注销，真实验证新登录成功。RSA 加密元数据有离线向量验证，当前学校返回不需要 RSA，因此不宣称 RSA 分支已在现网验证。
2. SCAUNET_1x 使用固定同名网络配置、当前调用者 EAP 数据，避免随机配置名和再次索取密码。该机普通用户实际登录及核心重启后重登已通过，无需人工补输凭据。产品不修改 Windows 系统网络名称。
3. 套餐摆脱对已有有线配置的依赖，绑定有效物理接口。查询去重、短暂失败退避、重连代际隔离和可见页面刷新，处理首次登录/切网后缓存长期未知的问题。
4. 启动支持跟随上次模式和有序备用。真实 Backend 的启动入口和核心恢复已调用验证；还包含离线备用切换、取消、重复查询、晚到响应和进程身份竞争测试。
5. WLAN 初始化和自身关联开始前后的旧通知竞争增加有限等待与归属判别。网络已放行但未确认账号时只报告网络可用。

## 前序失败与证据纠正

保留本地历史运行，没有覆盖失败日志。第 27 轮旧 authAPI 登录成功后状态查询失败，终止码为 6；旧脚本遗漏终止码条件而误写成功，该轮明确作废，后续已修复成功判据。第 29 轮重登成功但立即 DNS 探测失败，增加等待网络地址稳定后重测。第 33 轮虽然通过，实际运行在管理员令牌中，不作为普通权限证据。

第 34 轮普通权限认证成功，但实验进程观察名单遗漏探针，回滚过早，整轮失败；名单及精确进程回收已修正。第 36 轮 Web 在发送 HTTP 前以环境终止码 4 退出，当时没有保存详细异常，因此不宣称已经证明其唯一根因；第 37 轮和最终第 38、41 轮均新登录通过。正式成功结果只使用最终构建四轮及明确标注的历史证据。
